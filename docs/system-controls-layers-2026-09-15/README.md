# 暂停与设置入口层级检查

2026-09-15：暂停、设置及其展开面板归属当前页面的普通 UI 层；全屏遮罩按各自原有层级覆盖它们。身份选择与身份揭示期间仍不渲染入口。

## 根因与修复

原 `GammaSlider` 将整组按钮和设置面板通过 `createPortal` 挂到 `document.body`，自身 `z-index: 1800`。页面 `#root` 和对局 `.toe-battle-root` 分别形成层叠上下文，因此区域探寻的 `z-index: 300`、甚至身份选择的 `9998` 都只在自己的父层内排序，无法覆盖 body 上的设置入口。单独继续提高各个弹窗数字会保留这一结构问题。

修复采用现有页面层级：

- `GammaSlider` 直接返回组件 DOM，不再将普通系统控件 portal 到 body。
- 对局中将它放在 `.toe-battle-root` 的直系子节点，位于棋盘缩放与震屏容器之外。
- `.toe-settings` 使用 `z-index: 4`；对局的直系选择器显式保留 `position: fixed` 和 `z-index: 4`，避免全局 `.toe-battle-root > *` 的默认样式将它改为相对定位、降至棋盘层。
- 主界面和结算页继续原位置渲染，按钮锚点、尺寸曲线、菜单行为不变。

## 保留的例外与定位要求

设置展开面板是按钮的子元素，与按钮同层；打开设置不会自动暂停游戏。模态遮罩出现时，展开面板也随入口一起位于其下，不单独提升层级。

目标选择与教学操作步骤的穿透是交互要求，不能仅为屏蔽系统按钮而把它们全部改成阻塞遮罩。非阻塞光效、飘字、提示卡仍按原有 `pointer-events` 工作。专用全屏闪光层 `FullscreenLightLayer` 的 body portal 和高层级用于真实全屏光效，继续保留。

`.toe-battle-root` 自身不得承载 `transform`、`filter`、`perspective` 等会改变固定定位包含块的效果；镜头背景动画留在伪元素，震屏留在 `BattleSceneContent`。系统按钮必须位于这些效果和棋盘 `zoom` 容器之外。移动端所有坐标均使用同源横屏 iframe 的内部逻辑视口，不读取宿主竖屏尺寸或把入口移到父窗口。
