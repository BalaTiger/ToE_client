# 主界面竖屏放大与辅助按钮定位 · 2026-09-15

本次调整解决PC竖屏按整张舞台留白缩放导致主体过小、辅助按钮随舞台缩到难以辨认的问题。[上一轮实现记录](../start-screen-fixed-2026-09-15/README.md)保留当时的构图、素材及验证结果；本记录更新缩放几何和网页边缘按钮的锚点。

## 主体缩放

设计舞台仍为1490×1056，主体内部坐标、字号及相对大小不变。标题、职业与规则面板、两个主按钮统一等比缩放，不因窗口比例改变而重新排版。实际主体范围为 `x=265..1225`，底缘按 `y=935` 保守计算；舞台左右空白可以超出视口。

[`getStartScreenScale`](../../src/components/start/startScreenGeometry.js) 取以下三项最小值：

- 可见内容宽度：`max(1, vw - 32) / 960`，宽度受限时左右各留16px。
- 原舞台高度比例：`vh / 1056`，空间足够的横屏沿用原来倍率。
- 页脚避让：`max(1, vh / 2 - footerClearance) / 407`，其中 `407 = 935 - 1056 / 2`，`footerClearance = 26 + 57.37 × controlScale`。页脚高按实际控件倍率计算，另留14px下边距及12px间隔。

缺失、非正或非有限的视口输入继续按对应设计尺寸回退。617×1009窗口的主体倍率由约0.414094提高至0.609375，放大约47%；可见主体宽585px，左右各16px。标题与主按钮宽度比、按钮底图与内部文字大小比例不变。

“古神沉眠之时”介绍继续完整保留为两行，每行禁止自动换行；`text-size-adjust: 100%` 防止移动浏览器单独放大文字。背景仍独立铺满窗口，窗口比例只改变主体整体适配倍率及外围背景展示范围。

## 辅助控件

辅助控件移出主体设计舞台，固定在网页边缘。它们自己的底图和内部文字仍整体缩放。

| 控件 | 网页锚点 |
| --- | --- |
| 两个Debug按钮 | 左上，距左、上各14px；极窄窗口允许在该区域折行 |
| Gamma / 音效触发器 | 正上居中，上距0 |
| 关于作者与反馈 | 左下，距左、下各14px |
| 版本更新计划 | 右下，距右、下各14px |

[`getStartScreenControlScale`](../../src/components/start/startScreenGeometry.js) 独立计算控件倍率：先采用 `clamp(0.92, 0.9 + min(vw, vh) / 10000, 1.12)`，再由 `max(1, vw - 40) / 520` 限制极窄窗口下两只260px页脚按钮的总宽度。617×1009时倍率为0.9617，每个页脚按钮约250px宽，避免随主体缩为小字。Debug的可用区域与正中设置按钮分开，窄窗仅调整Debug按钮组的换行。

设置面板与其他弹窗继续使用视口坐标，设置面板高度按触发器高度和底部留白限制。移动端持久横屏iframe不变，菜单读取内部逻辑尺寸，翻转不重建应用或重置状态。本次复用既有素材，未重新生成图片。

## 已完成的验收

- 617×1009：主体左右各16px，辅助控件采用0.9617倍率，页脚按钮约250px宽。
- 400px宽窄窗：辅助按钮无交叠，Debug可折行。
- 聚焦Vitest：198项通过。

- 900×474：主按钮底部390.18px，页脚顶部405.66px，实际画面无交叠。
- 1600×1000和1900×1000：主体倍率同为0.94697，标题与主按钮宽度之比维持1.454545；各窗口介绍均为两行，页面无滚屏。
- Debug左、上距14px，设置正上居中；页脚距左右、下边缘各14px。400px宽时Debug右缘134px，设置左缘161.93px，无交叠。
- 视听设置、关于作者与版本计划入口均已点击验证；400px宽时设置面板位于x=30～370内。
- ESLint、生产构建通过；资源清单仅构建时间变化，已保留原时间。构建仍有既有的大包体提示。
