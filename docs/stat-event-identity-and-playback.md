# 属性事件身份与动画事务

2026-09-13：连续追捕与黑夜结算的归属迁移。

## 字段职责

| 字段 | 职责 |
| --- | --- |
| `statEvent.id` | 一次属性事件的稳定身份。规则生成时分配，复制、JSON 传输、视角旋转和动画投影保持不变。 |
| `statEvent.seq` / `_statEventSeq` | 结算批次及增量游标。一个批次可包含多个事件；不能用来认领伤害或去重。 |
| `visualEventId` | 动画步骤所属的视觉事件。不同事件不能因为属性数值相同而互相认领。 |
| `sourceStatEventIds` | 死亡、复活揭示等非属性条步骤对应的源属性事件。 |
| `statEventIds` | 摸牌、邪神遭遇、信仰退出等元数据引用的属性事件集合。 |
| `transactionId`、`order`、依赖字段 | 规则事务及事件顺序。`causedByEventId`、`targetResolutionEventId` 指定前置事件。 |

`ensureStatEventId` 不消耗玩法使用的 `Math.random`。两次独立的相同伤害应有不同 ID；同一次伤害被专属效果、通用包装事件和属性日志引用时必须复用原事件，不能重新调用 `buildStatEvents` 构造一份。

## 生成、准备和播放

1. 规则层生成带 ID 的属性事件，将同一份事件交给其视觉所有者及规则日志。
2. 编译层按事件及阶段产生完整步骤，记录 `compiledSchemaVersion` 与 `stepManifest`。
3. `prepareAnimationTransaction` 适配旧数据、处理旧队列顺序、截断终局后的步骤、检查显式依赖，并计算可以在完成后消费的事件 ID。
4. 播放器接收带 `queueSchemaVersion` 和步骤清单的成品。它处理计时、视觉状态及日志，不再执行黑夜归属推断或伤害重排，也不补猜可消费的事件 ID。

队列发生了删步或改序而清单未相应重建时，播放器拒绝接收。取消或重置仍清空待消费事件；只有队列完成才提交准备阶段证明完整的事件。

## 完整覆盖

`getVisualEventIdsCoveredByAnimationQueue` 将事件的预期编译步骤与实际队列比较。事件 ID 在队列中出现过，不能证明事件已完整呈现。

- `HP_SAN_LOSS` 的同一个属性 ID 必须同时具有 HP 和 SAN 投影。
- 致死结算必须具有伤害、断头台及死亡结算；复活流程必须保留揭示与恢复。
- 掉包必须具有完整卡牌转移，不能只有技能锁定。
- 步骤按事件内顺序匹配，并计算重复步骤的次数；不同角色或卡牌不互换。
- 通用属性包装可被真正拥有同一属性事件的专属视觉事件覆盖，但仍要求全部投影和后果。
- 准备阶段对队列中同时存在的显式前后依赖检查实际播放顺序。父事件包含嵌套结算的情况单独处理。

## 旧数据兼容

`adaptLegacyStatEventGraph` 在准备/编译入口处理缺少 ID 的旧数据及旧 `statEventSeqs`、`statSeqs` 元数据。它依次使用已有 ID、共享对象引用、明确的所有者及唯一来源证据；只有兼容路径允许用完整旧数据内容建立关联。

旧黑夜目标只有 `statSeq` 时，由 `adaptLegacyApophisTargetOwnership` 做一次受限转换。新格式明确给出的空属性集合不会触发旧推断。同序号出现多个可能的 SAN 损伤，或同一旧属性可能属于多个所有者时，返回明确诊断，准备入口拒绝猜测归属。

无规则事件 payload 的旧式不透明视觉 ID 仍可按调用方声明传递。完整覆盖保证针对当前状态中可取得 payload 的已知事件；这项兼容不能用于绕过已知事件的完整性检查。

## 防回归入口

`check-animation-transactions.mjs` 禁止恢复退役的按属性序号认领 API，以及在播放器重新调用黑夜归一化。新增回归覆盖稳定 ID、旧数据歧义、完整投影、最终事务准备、真实 AI 连续追捕及播放器消费边界。

断头台截图准备是另一条独立链路：截图就绪后才启动切割、音效、震屏和动画计时；截图失败或超时有有界降级，过期回调不能作用于后续动画。它不依赖 HP 是否已经归零来决定能否截图。
