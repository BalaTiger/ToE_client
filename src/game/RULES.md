# 游戏流程与事件结算规则

本文是回合流程、事件调度和结算快照语义的实现规范。卡面描述决定单张牌的效果；当卡面没有说明程序应在哪个阶段登记、何时读取状态时，以本文为准。

## 标准回合阶段

以一个角色的可见回合为起点，阶段顺序为：

`turnBanner → turnStart → draw → action → discard → endTurn → turnBoundary`

1. **回合悬浮文字（`turnBanner`）**
   - 独立播放“某角色的回合开始”悬浮文字，用于明确告知回合已经交替。
   - 该阶段只负责提示，不触发任何卡牌、神力、伤害、治疗或摸牌效果。
   - 保持短文本，不把阶段说明拼入大号悬浮文字。
2. **回合开始阶段（`turnStart`）**
   - 登记并按回合开始优先级结算被动、伤害、治疗和主动神力。
   - 当前明确顺序包括：黑山羊幼仔伤害 → 中毒伤害 → 两人一绳到期治疗 → 主动神力。
   - 两人一绳治疗设计为晚于其他回合开始伤害；若绳索在先前伤害中已经断裂，结算治疗时不再生效。
3. **摸牌阶段（`draw`）**
   - 先处理仍然有效的额外摸牌，再处理固定摸牌。
   - 每次翻牌及其效果完整结算后，才进入下一次摸牌。
4. **行动阶段（`action`）**
   - 摸牌及其所有决策、检定和中断续算完成后，当前角色进入行动阶段。
   - 当前角色执行技能、打出卡牌、休息等行动。
   - 真人玩家点击“结束回合”后离开行动阶段。
5. **弃牌阶段（`discard`）**
   - 检查当前角色的手牌上限；超限时必须先完成弃牌。
   - 手牌上限弃牌及其连带效果属于弃牌阶段，不属于回合结束事件。
   - 弃牌阶段结束后才进入回合结束阶段。
6. **回合结束阶段（`endTurn`）**
   - 在阶段开始时登记回合结束事件，并按统一优先级依次结算。
   - 例：克苏鲁休息摸牌、逆流、撒托古亚发放黏液、无尽通道。
7. **回合边界（`turnBoundary`）**
   - 承载当前角色结束后、下一角色开场前的状态和演出交接。
   - 它是流程衔接边界，不等同于下一角色的回合开始事件。
   - 边界完成后，流程进入下一角色的 `turnBanner`，形成完整循环。

代码中的阶段名称统一定义在 `turnFlowStages.js`；演出队列中的开场子阶段定义在 `turnAnimState.js`。

## 翻面跳过回合

翻面角色轮到行动时：

- 仍然拥有一次可见的回合交替，因此播放 `turnBanner`；
- 将角色翻回正常状态，并记录“醒来，跳过本回合”；
- 不进入弃牌、回合结束、回合开始、摸牌或行动阶段；
- 不执行中毒、黑山羊幼仔、两人一绳、克苏鲁摸牌等任何阶段事件；
- 不消耗“下个正常回合”才应生效或到期的状态。

因此，“播放了回合开始悬浮文字”不代表执行了规则意义上的回合开始阶段。

## 回合开始事件优先级

回合开始事件按以下优先级登记和执行，数值越小越早：

1. 被动神牌
2. 被动神牌衍生物
3. 其他被动牌或状态
4. 主动神牌
5. 其他主动牌或状态

同一优先级按注册表中的登记顺序结算。当前注册表示例：

- 黑山羊幼仔：被动神牌衍生物；
- 中毒：其他被动状态；
- 两人一绳到期治疗：其他被动状态，但登记在伤害之后；
- 朱雀照牌、奈亚借身：主动神牌。

玩家、联机真人和 AI 必须共用 `turnStartEvents.js` 的注册表。不得为 AI 另写一套顺序，也不得只声明优先级常量而在实际流程中硬编码另一种顺序。

## 回合结束事件优先级

回合结束事件按以下顺序结算：

1. 主动神牌
2. 主动神牌衍生物
3. 其他主动牌或状态
4. 被动神牌
5. 被动神牌衍生物
6. 其他被动牌或状态

当前重要例子：

- 克苏鲁休息摸牌属于主动神牌事件；
- 逆流属于其他主动事件，在当前角色的回合结束阶段反转轮换方向；
- 撒托古亚发放黏液属于被动神牌事件；
- 无尽通道属于其他被动牌事件。

玩家和 AI 必须共用 `endTurnEvents.js` 的事件登记与优先级。事件需要玩家决策时可以暂停，决策完成后从调度游标继续，不能重新执行已经完成的事件。

## 卡牌获得与邪神信仰结算

本节描述一次“获得并结算卡牌”的内部子阶段。它们依附于摸牌、蛊惑等来源事件，不改变前文的外层回合阶段顺序。

### 蛊惑的规则定义

技能【蛊惑】定义为：

> 将一张手牌赠送给目标，视为目标摸到这张牌并强制收入；邪神牌视为强制信仰。

因此，蛊惑必须复用普通“摸到卡牌后收入或信仰”的完整结算语义。区别只在于卡牌来源、是否强制接受，以及赠牌前置演出；不能为蛊惑另写一套信仰顺序。

### 卡牌获得的四个子阶段

一次卡牌获得按以下顺序编排：

1. **获得阶段（`acquisition`）**
   - 蛊惑依次播放 `SKILL_BEWITCH → CARD_TRANSFER → DRAW_CARD`。
   - 普通牌堆摸牌从相应的抽取、翻牌演出开始。
   - 本阶段只表达卡牌从来源到接收者，不提前展示后续信仰或牌效的最终状态。
2. **遭遇邪神阶段（`godEncounter`）**
   - 仅邪神牌存在；区域牌跳过本阶段。
   - 推进接收者的邪神遭遇次数。
   - 结算遭遇造成的 SAN 损失，以及该损失引发的完整检定链。
   - 本阶段仍显示接收者原有的信仰状态，新邪神徽章不得提前出现。
3. **收入／信仰变更结算阶段（`acceptance`）**
   - 区域牌：执行强制收入后的区域牌效果及其连带结算。
   - 邪神牌：按下文“信仰变更的内部顺序”处理旧信仰、新信仰和被抛弃角色。
4. **信仰时邪神之力阶段（`onWorshipPower`）**
   - 只执行“建立信仰时立即触发”的邪神之力。
   - 例如 APO 日食、SHU 黑山羊、ZHU 点亮，以及对应的神力阻断反馈。
   - 普通持续能力或其他触发时机的能力不应混入本阶段。

统一编译顺序为：

```js
[
  ...acquisition,
  ...encounter,
  ...acceptance,
  ...onWorshipPower,
]
```

### 信仰变更的内部顺序

邪神牌进入 `acceptance` 后，严格按以下顺序结算：

1. **解除接收者的原信仰**
   - 仅当接收者原来信仰其他邪神时执行。
   - 先让原邪神之力标签消失，再播放弃置原邪神牌的动画，然后播放改信造成的 SAN 扣减。
2. **结算解除原信仰的连带效果**
   - 例如 SAN 损失触发的检定翻牌、检定结果和后续状态提交。
   - 该链完全结束前不得建立或展示新信仰。
3. **建立并展示新信仰**
   - 提交接收者的新邪神信仰。
   - 让新的邪神之力标签出现，并播放标签升级特效和角色面板 `GOD_HIGHLIGHT`。
   - `GOD_HIGHLIGHT` 是新信仰正式进入可见状态的边界。
4. **处理被新邪神抛弃的原信徒**
   - 若该邪神已有因此次信仰而被抛弃的角色，先让这些角色的邪神之力标签消失。
   - 再播放其邪神牌弃置动画和“被邪神抛弃”造成的 SAN 扣减。
5. **结算被抛弃角色的连带效果**
   - 例如 SAN 损失触发的完整检定链。
   - 全部完成后，`acceptance` 才算结束，随后才能进入 `onWorshipPower`。

没有旧信仰或没有被抛弃角色时，跳过对应步骤，但不得改变其余步骤的相对顺序。区域牌的收入效果也不得借用邪神高亮作为排序锚点。

### 属性变化按原因归属阶段

HP/SAN 动画属于哪个子阶段，由产生它的规则原因决定，不能按 `HP_DAMAGE`、`SAN_DAMAGE` 等动画类型重新分桶或统一移动：

- 遭遇邪神造成的 SAN 损失属于 `godEncounter`；
- 改信造成的 SAN 损失属于 `acceptance` 的旧信仰解除步骤；
- 被邪神抛弃造成的 SAN 损失属于 `acceptance` 的抛弃步骤；
- 新信仰建立后立即触发的神力属性变化属于 `onWorshipPower`；
- 区域牌自身造成的属性变化属于 `acceptance`。

禁止通过“把所有属性动画放到高亮前／后”来修补顺序，也禁止从最终动画队列反推事件属于哪个阶段。规则结算应先输出带阶段的语义事件，再由统一编译器顺序展开。

### 检定链是所属阶段的原子子序列

任何 SAN 损失触发的检定链必须完整保留在产生该损失的阶段中，不得拆散到高亮或其他阶段两侧。典型原子顺序为：

```text
SAN_DAMAGE
→ VISUAL_LOCK
→ 检定 DRAW_CARD
→ 检定结果动画
→ STATE_PATCH
```

只有该原子序列完成后，才能进入同级的下一步骤或下一个卡牌获得子阶段。

### 分阶段快照与视觉提交

卡牌获得结算必须保留中间边界，不能只提供最终 `playersAfter`。语义上至少需要：

```js
{
  playersAfterGift,
  playersAfterEncounter,
  playersAfterAcceptance,
  stateAfterPower,
}
```

这些快照必须保证：

- `playersAfterGift` 只反映赠牌已经发生；
- `playersAfterEncounter` 仍保留原信仰，并包含遭遇及检定结果；
- 新邪神标签只在 `acceptance` 的建立新信仰步骤出现；
- 被抛弃角色的标签、邪神牌和 SAN 变化按前述顺序提交，不能从最终状态提前泄漏；
- APO、SHU、ZHU 等信仰时神力的视觉状态只在 `onWorshipPower` 出现；
- 任意直接 `STATE_PATCH`、`VISUAL_LOCK` 或最终玩家快照都不得让后续阶段的徽章、弃牌或属性结果提前出现。

普通摸牌与蛊惑应共用同一套卡牌获得解析和动画编译模型，仅用参数表达来源差异，例如：

```js
{
  source: 'bewitch',
  forcedAccept: true,
  forcedWorship: true,
  giverIdx,
  receiverIdx,
}
```

不得依赖 `reorderBewitchGodHighlight` 一类事后猜测式重排来维持规则顺序。

## 状态读取与快照语义

核心规则：

> **若判定与手牌相关，则采用动态重算；否则在阶段开始时锁定。**

### 与手牌相关：动态重算

凡是判定依赖手牌中“是否存在、位于哪里、有几张、当前归谁持有”的内容，都必须在该事件实际轮到结算时读取当前手牌，不能只使用阶段开始时的手牌快照。

典型例子：

- **无尽通道**：轮到该事件时，重新检查当前手牌中的通道及其左侧卡牌。之前的克苏鲁摸牌、换手或其他效果可能新增、移走或改变通道位置。
- **撒托古亚黏液额外摸牌**：不在摸牌阶段开始时锁定额外摸牌次数。每次准备额外摸牌时，只检查当前摸牌者此刻仍持有的黏液；先令一张黏液消失，再完成它对应的一次额外摸牌，然后重新检查。
- 黏液在中途被消耗、弃置或转移给其他角色后，不再为原角色提供额外摸牌，也不能跨角色搜索并消耗该牌。
- 中途新获得且仍由当前摸牌者持有的有效黏液，在下一次动态检查时可以参与结算。

动态重算只影响尚未结算的当前或后续事件，不会倒退并重做已经完成的高优先级事件。

### 与手牌无关：阶段开始时锁定

不依赖手牌内容的次数、数值、候选事件和固定参数，在对应阶段开始时锁定。后续事件改变状态时，不回头修改已经登记的参数。

典型例子：

- **克苏鲁休息摸牌**：阶段开始时锁定本次应摸张数；结算中途即使神力等级等状态发生变化，也不改变剩余次数。
- **逆流**：阶段开始时锁定此前登记的反转次数；多次逆流按次数奇偶决定最终方向。
- **撒托古亚回合结束发放黏液**：发放数量按阶段开始时的神力等级等非手牌状态锁定。
- 事件造成的伤害量、已选目标等非手牌参数，除非卡面明确要求结算时重新判断，否则使用登记时的值。

“阶段开始锁定”不取消结算时的基本合法性检查。例如角色已死亡、目标已不存在，或两人一绳已被先结算的伤害扯断时，事件可以失效；这属于确认事件是否仍可合法执行，不是重新计算其锁定参数。

### 中断与续算

- 进入神牌选择、摸牌选择、黏液平衡、朱雀藏牌等决策时，保存未完成事件和必要的锁定参数。
- 决策完成后从中断点继续，不得重播已经消耗的牌或重新登记整个阶段。
- 动态手牌判定在恢复时重新读取当前手牌；锁定参数则沿用中断前保存的值。
- 朱雀在“黏液已消失、额外摸牌尚未翻开”之间中断时，保存的只是“一次待完成的额外摸牌”，不能再次消耗黏液。

## 规则结算与演出边界

- 游戏状态是权威结果，动画队列只负责按正确阶段展示结果。
- `turnBanner`、`turnStart` 和 `draw` 必须是可区分的演出阶段，不能把后续摸牌效果提前夹入悬浮文字之前。
- 中毒属于 `turnStart`，不得归入 `draw`。
- 回合开始伤害必须在摸牌翻牌之前播放；两人一绳治疗在这些伤害之后播放。
- 下回合的数值事件不得进入上一个 AI 行动的回放事务，否则会在回合悬浮文字前泄露结果。
- HP/SAN 的权威状态与可见数值时间线仍遵循项目根目录 README 中的 presentation boundary 约定。

## 新增或修改阶段事件时的检查清单

1. 明确事件属于弃牌、回合结束、回合开始还是摸牌阶段。
2. 在共享注册表中登记优先级，不为玩家、AI、联机分别复制顺序。
3. 判断事件条件或参数是否依赖手牌：
   - 依赖手牌：实际结算时动态重算；
   - 不依赖手牌：阶段开始时锁定。
4. 明确事件中断时保存的是锁定参数还是仅保存续算位置。
5. 若事件属于卡牌获得，明确其位于 `acquisition`、`godEncounter`、`acceptance` 或 `onWorshipPower`，并提供相应的阶段快照。
6. 确认检定链没有被高亮、弃牌或下一阶段动画拆散。
7. 确认翻面跳过路径不会误执行该事件。
8. 为规则顺序、动态/锁定语义、阶段快照和动画阶段补充针对性测试。
