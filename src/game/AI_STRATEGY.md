# AI 策略框架

规则依据仍是 `RULES.md` 和卡牌描述。策略负责选合法动作，真实结算模块负责修改游戏状态与产生视觉事件。

## 决策流程

1. `createAiObservationState` 提取当前 AI 有权知道的状态：自己的手牌、公开手牌、仍有效的窥视记忆、公开身份和场上效果。对手暗牌、隐藏身份、牌堆顺序、密封选择与动画快照不会进入预演。
2. 每个决策适配器枚举合法动作，调用真实规则函数，在状态副本上预演直接后果。预演不能提交副本中的视觉事件。
3. `rankAiActions` 按阵营胜负、存活、资源与局面价值依次比较。适配器的启发式评分只能影响最后一层，不能盖过已确认的胜负和存活。
4. 正式入口只取选中的动作，重新在真实状态上结算。中断必须保留续接，不能把暂时停下的状态当成最终结果。

`runAiPreview` 为每个候选提供相同的独立随机样本，并在正常返回或异常时恢复随机函数、视觉事件序号、属性事件身份及衍生牌 ID。接口同步执行，不允许异步预演。

## 已接入的决策

| 模块 | 决策与结算边界 |
| --- | --- |
| `aiDiscardChoices.js` | 同归深渊的受伤/弃牌、上限弃牌、追捕的匹配弃牌/放弃；预演天平、绳索、倒刺及伤害反应 |
| `aiHandLimitDiscard.js` | 正式逐张上限弃牌；暂停时保存回合收尾进度，恢复后不重复技能和休息 |
| `sameAbyssResolution.js` | 同归深渊正式结算共用入口；逐张重算来源手牌，中断后继续已经选择的弃牌义务 |
| `aiPublicChoices.js` | 先到先得、灵龟的公开收入，包含真实公开收入触发 |
| `aiStoneChoice.js` / `publicChoiceResolution.js` | 解读石刻的收入与 SAN 成本，以及公开选择阶段的共享结算 |
| `caveDuel.js` | 穴居人战争按公开对手手牌比较；隐藏出牌仍使用不读取暗牌的保守估值 |
| `aiRulePreview.js` | 收入和蛊惑调用 `applyFx`；修正 HP/SAN 结算次序、阵营胜负和可宣布寻宝胜利的边界 |
| `aiReactionPreview.js` | 有限展开虚化、黏液等反应；已知身份按自身目标选择，未知身份评估对观察者不利的合法回应 |
| `victory.js` | 与回合引擎共用即时胜负规则，寻宝集齐另按合法宣布边界检查 |

本地 AI、恢复处理、headless 和相应联机接管入口使用这些适配器。正式结算仍沿用现有回合管理器及视觉事件事务。

## 当前搜索范围

这是有限深度的策略框架，不保证整局最优。小手牌的弃牌顺序会枚举，较大分支使用有界搜索；伤害反应也有节点预算。复杂卡牌的后续选择、神牌信仰、未知摸牌和随机检定尚未全部展开。

无法完整证明的后果必须标记 `_aiPreviewIncomplete` / `_aiPendingResolution`，并计入不确定风险。不得把一次检定采样、尚待处理的反应或续摸前临时集齐当成必然胜利。普通局面仍保留部分原有启发式作为次级估值，便于逐步替换。

## 扩展与回归

新增决策时先列出动作与公开输入，再接真实规则函数；不要在策略里复制伤害数值或重新实现胜负规则。新增公开状态字段时同时检查观察白名单，不可直接复制整个权威状态或 `abilityData`。

回归应覆盖明确反例、隐藏信息替换后选择不变、输入与运行时计数不变，以及中断恢复。对于依赖手牌顺序的旧演出测试，用确实会选择该动作的局面保留原演出断言，不能通过禁用策略来制造旧行为。

共享规则修改运行 `npm run test:run`、`npm run lint`、`npm run build`；headless 批次保留完整胜负与演出连续性检查。不要提交仅生成时间改变的资源清单。
